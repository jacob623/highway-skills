# Northwind Restock Alerts

## Architecture Reference

Architecture: RA22140b24
Title: Scheduled Restock Alert Service
Status: accepted

## Variation Choices

- Scheduler: GitHub Actions cron schedule, Mondays at 06:00
- Alert channel: Email to the warehouse lead

## Coverage

| Responsibility | Status |
|---|---|
| Start the check each week | covered |
| Read stock levels without writing them | covered |
| Send one alert listing items at or below their reorder point | covered |

Conformance: compatible

## Realized Interfaces

- Read-only stock query: Order service `GET /stock?below=reorder`
- Notification message: Email through the store's mail service

Conformance Evidence: None

## Limitations

Alerts go to one address.

## Technology Choice

Intent: A scheduler the team already runs.
Choice: GitHub Actions scheduled workflow
Reason: The team runs GitHub Actions for every repository.
Evidence: ADR03680218 and RI680202d2.

## Execution

Deployed by: GitHub Actions (RI680202d2)
Managed by: GitHub Actions (RI680202d2)
Language: None

## Context

Realizes the weekly restock alert decided in ADR4222f832. An instance is running and sends the alert every Monday.

## Implementation Summary

A scheduled GitHub Actions workflow calls the order service stock query with a read-only token, formats the items at or below their reorder point, and emails the list to the warehouse lead.

## Realized Capabilities

- Title: Weekly restock alert
  Realized By: GitHub Actions
  Evidence: The Monday workflow sends the alert email.
- Title: Reorder point check
  Realized By: Northwind Order Service
  Evidence: The stock query returns items at or below their reorder point.

## Runtime Components

- Restock workflow: Scheduler and alert sender
- Stock query: Stock reader

## Data Realization

Stock levels and reorder points are read from the order service and not stored.

## Integration Realization

The workflow calls the order service stock query and the store's mail service.

## Security Control Realization

CTLf124f030: The stock token is read-only and kept in repository secrets; no payment data is read.

## NFR Realization

NFRe124ce38: The query runs before business hours.

## Assumptions

The order service keeps the stock query stable.

## Risks

A failed run is noticed only by its absence.

## Constraints

No new paid vendors.

## Dependencies

GitHub Actions; Northwind Order Service; the store's mail service.

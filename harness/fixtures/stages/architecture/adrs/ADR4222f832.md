## Clarification Inputs

None

## Context

Problem: Items fall below their reorder point unnoticed, and orders wait for stock.
Forces: One-day shipping, no new paid vendors, and a team that already runs GitHub Actions.
Evidence: None

## Decision

Selected Option: OPT22f814e1
Selection Source: User-provided explicit selection
Decision Statement: Restock alerts run as a weekly scheduled pipeline job that reads stock levels and sends one alert.
Decision Authority: Store manager
Decision Rationale: It removes the manual check, uses the preferred platform, and adds no vendor.
Authorization: Proceed to Reference Architecture; implementation authorization is excluded.

## Decision Scope

Covers: How weekly restock alerts are produced and delivered.
Leaves Open: The alert channel and the exact schedule.

## Revisit When

Stock changes faster than weekly alerts can catch.

## Decision Confidence

Discovery Confidence: Medium
Confidence Considerations: The order service query has not been load tested.

## Alternatives Considered

### OPT22f814e1

Definition: Scheduled Pipeline Restock Job
Outcome: Selected
Reason: Removes the manual weekly check.

### OPT2f14c01e

Definition: Spreadsheet Restock Macro
Outcome: Evaluated
Reason: Viable but still depends on someone running it.

## Assumptions

The order service exposes stock levels through a read-only query.

## Risks

A failed run delays the alert by a week unless someone watches the pipeline.

## Consequences

Positive: The warehouse lead no longer checks stock by hand.
Negative: The team owns one more scheduled job.
Operational: Failed runs need an owner.
Governance: The job must not read payment data.

## Constraints

No new paid vendors (REQ0464e132).

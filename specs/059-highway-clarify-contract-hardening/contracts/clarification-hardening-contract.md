# Contract: Clarification Hardening

## Stable Identifier

Every supported source artifact maps to exactly one stable identifier:

```text
CLAR-<ARTIFACT-ID>
```

Examples: `CLAR-REQ000001`, `CLAR-DISC000001`, `CLAR-ADR000001`, `CLAR-RA000001`.

## Profile Discovery

Profiles are optional. Resolve the first available profile in this order:

1. Artifact-local profile explicitly declared by the source.
2. `.highway/library/clarification/<artifact-type>.yaml`.
3. `.highway/library/clarification/profile.yaml`.

No available profile is valid and must not fail processing. Profile vocabulary extends, rather than replaces, the default ambiguity vocabulary.

## Stable Consumer Fields

Every Generate, Update, Inspect, Read, Status, not-started, and blocked response exposes:

```yaml
artifact_id: REQ000001
exists: true
status: in-progress
open_findings: 1
resolved_findings: 0
total_findings: 1
path: requests/REQ000001-clarification.md
blocking_reason: None
```

Future versions may add fields but may not remove, rename, or change the data types of these fields.

## Regeneration

- No existing record: create the deterministic colocated record.
- Existing record: recalculate findings from current source.
- Preserve finding IDs when evidence is unchanged.
- Preserve valid responses and resolution history.
- Do not apply a response to changed or unrelated evidence.
- Any validation or write failure leaves the prior record unchanged.

## Revision and Conflict

`revision` is an integer. It starts at 1, increments exactly once after each successful Update, and is unchanged by failed Updates or conflicts. A conflict returns `action: update`, `status: conflict`, `expected_revision`, `actual_revision`, the exact conflict message, and `path`; it writes nothing, appends no history, and changes no revision.

## Finding Ordering

1. contradiction
2. missing_input
3. unknown_value
4. ambiguity
5. unresolved_assumption

Within a category: source artifact order, source field name, then finding identifier.

## Privacy

Before findings, artifacts, updates, or writes, redact passwords, credentials, tokens, connection strings, secrets, and regulated personal data from all retained content: findings, copied evidence, responses, history, and metadata. Use `<secret-redacted>` or `<pii-redacted>`.

## Status

- `not-started`: artifact does not exist.
- `in-progress`: artifact exists and `open_findings > 0`.
- `complete`: artifact exists and `open_findings = 0`.
- `blocked`: malformed artifact, missing required metadata, or invalid required template structure.

## Determinism

Identical inputs produce identical finding count, IDs, order, severity, and generated bytes. Results do not depend on timestamps, filesystem ordering, recency, environment values, randomness, model preference, semantic similarity, or architectural preference.

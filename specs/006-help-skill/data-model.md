# Phase 1 Data Model: Help Skill

## Skill Registration (per skill, in its own `SKILL.md`)

The declared facts about one skill under `.highway/skills/<id>/`. Extends the existing shape
(feature 001/004) with two new required fields (bold).

| Field | Location | Required | Notes |
|---|---|---|---|
| `id` | directory name | Yes | Kebab-case, unique across `.highway/skills/`. |
| `name` | frontmatter | Yes | Free-form display name. |
| `description` | frontmatter | Yes | Non-empty, <= 500 characters. |
| **`usage`** | frontmatter | **Yes (new)** | Non-empty, <= 500 characters. One-line guidance on how to invoke/use the skill. |
| `compatibility` | frontmatter | No (defaults `all`) | One of `all`, `github-copilot`, `claude-code`, `cursor`. |
| `metadata.version` | frontmatter | Yes | Semantic version `MAJOR.MINOR.PATCH`. |
| `metadata.dependencies[]` | frontmatter | No (defaults empty) | List of `{path, version}`, each naming a file under `.highway/library/`. |
| `metadata.agent_exceptions[]` | frontmatter | No | List of `{agent, deviation}`. |
| body `## Purpose` ... `## Error Handling` (7 sections) | body | Yes | Unchanged from the existing authoring standard. |
| **body `## Example`** | body | **Yes (new)** | Exactly one copy-able example (typically a fenced code block). |

**Validation rules** (enforced by `.highway/tools/validate-skill.sh`):
- `usage` absent or empty -> `ERROR: [SCHEMA] missing required field 'usage'` (mirrors the
  existing `description` check).
- `usage` exceeds 500 characters -> `ERROR: [SCHEMA] field 'usage' exceeds 500 characters`.
- `## Example` section absent or empty -> `ERROR: [SCHEMA] missing required body section
  '## Example'` / `ERROR: [SCHEMA] body section '## Example' is present but empty` (mirrors the
  existing section-presence checks).

## Catalog Entry (`.highway/catalog/index.json`, per skill)

Generated by `.highway/tools/generate-catalog.sh` from each skill's Registration. Schema:
[contracts/catalog.schema.json](./contracts/catalog.schema.json) (supersedes
`specs/001-multi-agent-skill-suite/contracts/catalog.schema.json` by adding `usage`).

| Field | Type | Required |
|---|---|---|
| `id` | string | Yes |
| `name` | string | Yes |
| `description` | string | Yes |
| `usage` | string | Yes (new) |
| `compatibility` | string | Yes |
| `version` | string | Yes |
| `source_path` | string | Yes |

`Dependencies` and `Example` are intentionally **not** carried in the catalog (see research.md
R2/R3) — they are read directly from the target skill's `SKILL.md` only when a single-skill
request names that skill.

## Help Request

One optional input.

| Field | Type | Required | Notes |
|---|---|---|---|
| `skill_id` | string | No | When present, must (to resolve) match an existing entry's `id` in `catalog/index.json`. Absent means all-skills mode. |

## Single-Skill Response (one instance, for one resolved skill)

Produced by reading the target skill's `SKILL.md` directly (fresh, not from the catalog cache).

| Field | Source | Empty-case rendering |
|---|---|---|
| Name | `name` frontmatter | n/a (always present) |
| Description | `description` frontmatter | n/a (always present) |
| Dependencies | `metadata.dependencies[]` | literal `none` when the list is empty |
| Version | `metadata.version` | n/a (always present) |
| Usage | `usage` frontmatter | n/a (always present) |
| Example | body `## Example` | n/a (always present) |

Field order is fixed: Name, Description, Dependencies, Version, Usage, Example (FR-004).

## All-Skills Response (zero or more rows)

Produced by reading `catalog/index.json` once.

| Field | Source | Notes |
|---|---|---|
| Name | catalog entry `name` | |
| Usage | catalog entry `usage` | |
| Help | derived: literal `/help <id>` | `id` = catalog entry `id` (research.md R5) |

Field order is fixed: Name, Usage, Help (FR-006). Zero catalog entries renders one explicit
"no skills are registered" message (FR-008), never an empty table.

## State / lifecycle notes

- No entity here has a state machine; every response is computed fresh from the current
  contents of `.highway/skills/` (single-skill mode) or `catalog/index.json` (all-skills mode)
  at request time. There is no cached "help response" artifact.
- `catalog/index.json` is only as fresh as the last `generate-catalog.sh` run; this is an
  existing, unchanged property of the catalog (not introduced by this feature).

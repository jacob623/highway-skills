# Tasks: Multi-Agent Skill Suite

**Input**: Design documents from `/specs/001-multi-agent-skill-suite/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: Included. `plan.md`'s Testing strategy explicitly requires shell-based validation/test
scripts asserting schema conformance, catalog determinism, and adapter parity — these are treated
as requested tests for this feature.

**Organization**: Tasks are grouped by user story (from spec.md: US1 = P1, US2 = P2, US3 = P3) to
enable independent implementation and testing of each story.

**Scope reminder (FR-011)**: This feature ships the authoring **framework** only — `skills/`
ships with no concrete skill topics. Test fixtures live under `tools/tests/fixtures/`, not
`skills/`, so the shipped `skills/` directory stays empty of concrete content.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1, US2, US3)
- Include exact file paths in descriptions

## Path Conventions

Single project, repository root. Paths match `plan.md`'s Project Structure:
`skills/`, `tools/`, `tools/tests/`, `catalog/`, `.github/skills/`, `.claude/skills/`, `.cursor/rules/`.

- [X] T010 [P] [US1] Write `tools/tests/generate-agent-adapters.test.sh`: asserts `.github/skills/<id>/SKILL.md` and `.claude/skills/<id>/SKILL.md` are byte-identical to `skills/<id>/SKILL.md`; asserts `.cursor/rules/<id>.mdc` has `description` copied verbatim, `alwaysApply: false`, no `globs` field, and body copied verbatim below frontmatter; asserts existing `.github/skills/speckit-*/SKILL.md` files are untouched (byte-identical before/after run)

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies — start immediately
- **Foundational (Phase 2)**: Depends on Setup — BLOCKS all user stories
- **User Story 1 (Phase 3)**: Depends on Foundational only
- **User Story 2 (Phase 4)**: Depends on Foundational; reuses `tools/validate-skill.sh` from US1 (T011) but is otherwise independently testable
- **User Story 3 (Phase 5)**: Depends on Foundational; reuses `tools/generate-agent-adapters.sh` from US1 (T014) but is otherwise independently testable
- **Polish (Phase 6)**: Depends on US1, US2, and US3 all being complete

### User Story Dependencies

- **US1 (P1)**: No dependency on US2/US3. Fully self-contained MVP.
- **US2 (P2)**: Reuses `tools/validate-skill.sh` produced in US1 (T011); does not require US3.
- **US3 (P3)**: Reuses `tools/generate-agent-adapters.sh` produced in US1 (T014); does not require US2.

### Within Each User Story

- Tests written before the implementation they validate
- Shared library tasks (Foundational) before any script that uses them
- Each story's checkpoint task (final "run tests to green") comes last within that story

### Parallel Opportunities

- T002, T003, T004 (Setup docs) can run in parallel
- T007 (fixtures) can run in parallel with T008 (test runner) once T005/T006 exist
- T009 and T010 (US1 tests) can run in parallel
- T016 (US2 test) can start in parallel with US1 work once T011 exists
- T019 (US2 doc) can run in parallel with T017/T018
- T021 (US3 test) can run in parallel with US1/US2 work once T014 exists
- T023 (US3 doc) can run in parallel with T024
- T025, T027, T028 (Polish) can run in parallel; T026 should run after all stories are implemented

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Complete Phase 1: Setup
2. Complete Phase 2: Foundational (blocks everything)
3. Complete Phase 3: User Story 1
4. **STOP and VALIDATE**: run `tools/tests/validate-skill.test.sh` and `tools/tests/generate-agent-adapters.test.sh`; confirm SC-001 with the `tools/tests/fixtures/valid-skill` fixture
5. This alone proves the "write once, run on ≥2 agents" value proposition (SC-001)

### Incremental Delivery

1. Setup + Foundational → foundation ready
2. Add US1 → validate independently → MVP proven (write-once-run-anywhere)
3. Add US2 → validate independently → catalog/discovery proven
4. Add US3 → validate independently → new-agent extensibility proven
5. Polish → full quickstart.md run + security pass + docs

### Notes

- [P] tasks = different files, no dependencies
- Fixtures live under `tools/tests/fixtures/`, never under `skills/`, to keep the shipped
  framework free of concrete skill topics (FR-011)
- Verify each `*.test.sh` fails before its corresponding implementation task is done, then passes after
- Stop at each phase checkpoint to validate that story independently before proceeding

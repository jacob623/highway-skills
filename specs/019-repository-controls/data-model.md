# Data Model: Repository Controls

**Feature**: 019-repository-controls | **Date**: 2026-09-08

Two sets of artifacts, on opposite sides of a boundary. Which side a file sits on decides who
governs it.

## The boundary

```text
<project>/
├── .highway/                     ← Highway governs everything here
│   ├── skills/highway-controls/  ← the skill IS Highway content
│   ├── library/                  ← validated against the Skills Constitution
│   └── tools/
│
└── library/governance/           ← the USER governs everything here
    ├── controls.md               ← generated by the skill, owned by the user
    └── controls/CTLXXXXXX.md     ← authored via the skill, owned by the user
```

Highway writes into the lower half and governs none of it. The skill that does the writing sits in
the upper half and is governed fully.

## Entities

### Control

One file, `library/governance/controls/CTLXXXXXX.md`. YAML frontmatter, Markdown body.

| Field | Constraint | Owner |
|---|---|---|
| `id` | `CTL` + six digits. Allocated once, never reused, never changed | Skill allocates; immutable thereafter |
| `title` | Short name | User |
| `statement` | The obligation, in the user's words | User |
| `rationale` | Why it exists | User |
| `status` | Lifecycle state | User |
| `nfrs` | Present and empty in this phase | Reserved |

**No `version` field.** The baseline holds the only version — decided 2026-09-08, because two
counters over the same content can disagree with nothing saying which is authoritative.

### Baseline

The set of Controls, carrying one semantic version.

| Change | Increment |
|---|---|
| A Control added | MINOR |
| A Control edited without changing its obligation | PATCH |
| **A Control removed, or the baseline replaced** | **MAJOR** |

Removal is MAJOR because an identifier may be cited by a design document or an audit finding this
repository cannot see.

### Catalog

`library/governance/controls.md`. Generated. Holds:

- an index of every Control
- the baseline version
- **the next identifier to allocate**
- a statement that Controls are managed through the skill

**No timestamp**, so an unchanged baseline regenerates to an identical file.

### Identifier allocation

```text
next_id in the catalog          ← the authority
        │
        ├── Add:    take it, then increment it
        ├── Remove: leave it untouched
        └── Set:    take as many as needed, never reissue
```

Deriving the next identifier from the highest existing file would reuse `CTL000023` after
`CTL000023` was deleted. Recording it is why removal is safe.

## Relationships

```text
   Baseline ──1:N── Control ──0:N── NFR (reserved, empty this phase)
       │                │
       │                └── id: allocated once, cited elsewhere, never reused
       │
       └── version: the only version in the system
```

## Validation rules

| # | Constraint | Source |
|---|---|---|
| V1 | No Control file sits under `.highway/` | FR-001 |
| V2 | No Highway generator sweeps or indexes user Controls | FR-002 |
| V3 | The validator declines any file outside its framework root, by any path form | FR-003 |
| V4 | No identifier is ever reused | FR-010, FR-012 |
| V5 | An identifier never changes | FR-011 |
| V6 | Nothing is deleted without each loss being named | FR-018, FR-019 |
| V7 | The catalog is a function of the Controls and the next identifier | FR-008 |
| V8 | A Control carries no version | FR-031 |
| V9 | The relationship field exists on every Control | FR-030 |

## State transitions

```text
            Add                Update              Remove
   (none) ──────▶ active ─────────▶ active ─────────▶ (gone)
                    │                                    │
                    │  identifier fixed for life         │  identifier retired,
                    └────────────────────────────────────┘  never reissued
```

`status` is a user-owned field; the skill does not constrain its values in this phase. Only
existence and removal are modelled, because those are what the identifier guarantees depend on.

## Deliberately not modelled

| Not modelled | Why |
|---|---|
| Whether a Control is "good" | The skill advises and does not judge — `FR-026` |
| Whether a cited identifier still resolves | Out of scope; part of why removal is MAJOR |
| Per-Control history | Version control already holds it |
| NFRs and their relationships | Phase 2; only the field is reserved |

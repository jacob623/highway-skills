# Data Model: Discovery Option Review and Implementation Exploration

## Candidate Solution Option

A deterministic option already generated by Discovery.

| Field | Description | Validation |
|---|---|---|
| Option ID | Discovery-scoped `OPT######` identifier | Must be unique within the Discovery and resolve to an existing option |
| Title | Stable option title | Required and deterministic |
| Summary | What the option is and how it addresses the Request | Required for review |
| Benefits | Expected strengths and value | May be empty only when explicitly reported as unavailable |
| Risks | Material drawbacks and failure modes | May be empty only when explicitly reported as unavailable |
| Assumptions | Conditions that must remain true | May be empty only when explicitly reported as unavailable |
| Dependencies | Platforms, products, vendors, integrations, services, and capabilities | Use `None` when no dependency is known |
| Alignment evidence | Request, Objective, Control, and NFR relationships | Read-only projection of accepted evidence |

## Option Review

A transient read-only presentation derived from one Candidate Solution Option and accepted context.
It is not a separately allocated or persisted artifact.

Required sections:

1. Summary
2. Request Alignment
3. Objective Alignment
4. Control Alignment
5. NFR Alignment
6. Benefits
7. Risks
8. Assumptions
9. Dependencies

A missing relationship or evidence source is represented as unavailable or `None`; it is never inferred
as an accepted relationship.

## Option Comparison

A transient read-only presentation for two distinct options from the same Discovery.

| Field | Description | Validation |
|---|---|---|
| Left option | First resolved option | Must exist in the active Discovery |
| Right option | Second resolved option | Must exist, differ from left option, and share the Discovery |
| Comparison basis | Existing option and alignment evidence | Does not recalculate or mutate recommendation scores |
| Advisory label | States that comparison informs evaluation only | Required |

## Reference Implementation

An optional advisory example of a product, platform, service, vendor, integration, or combination
that could realize an option.

| Field | Description | Validation |
|---|---|---|
| Name | Human-readable implementation example name | Required when an example is present |
| Components | Products or services composing the example | Optional, explicit when known |
| Purpose | Capability or realization purpose | Required when an example is present |
| Key capabilities | Capabilities relevant to the option | Optional, evidence-grounded |
| Evidence source | Accepted or explicitly qualified source | Required for non-Unknown claims |
| Advisory status | States that the example is not a commitment | Always present |

Reference Implementations are not architecture decisions, approvals, procurement commitments, or
implementation authorizations.

## Example Realization Matrix

An optional informational comparison of Reference Implementations.

| Column | Meaning |
|---|---|
| Product | Product, platform, service, or combination name |
| Purpose | Intended realization purpose |
| Key Capabilities | Relevant capabilities |
| Estimated Cost | Qualified range, Low/Medium/High, or `Unknown` |

Rows are ordered deterministically by implementation name unless the owning Discovery contract
specifies a more specific stable order.

## Cost Consideration

An optional advisory cost statement attached to an implementation example or option.

Allowed value forms:

- `Low`, `Medium`, or `High`
- A clearly bounded monetary range such as `$10-$50/month`
- `Unknown` when evidence is unavailable, incomplete, conflicting, or not reliable enough to state

Cost values do not participate in candidate scoring, recommendation ranking, tie-breaking, or ADR
selection.

## Discovery Completion Guidance

A transient completion projection containing:

- Candidate Solution Options
- Comparison Matrix
- Recommended Option
- Recommendation rationale
- Review prompts for describing, comparing, viewing examples, and viewing costs
- Explicit advisory statement and ADR next-step ownership

This guidance does not add a decision state to Discovery.

## Relationships and Boundaries

- One Discovery contains two through five Candidate Solution Options.
- One Option Review references exactly one Candidate Solution Option.
- One Option Comparison references exactly two distinct Candidate Solution Options from one Discovery.
- One Candidate Solution Option may have zero or more Reference Implementations.
- One Reference Implementation may appear in one or more realization matrices but remains advisory.
- One Discovery Recommendation references one recommended option but does not select it for ADR.
- One ADR may later select an option from the Discovery; ADR owns that selection and all decision content.

## State and Mutation Rules

- Discovery analysis produces a proposed record and advisory recommendation.
- Option review, comparison, example exploration, and cost exploration are read-only interactions.
- No exploration interaction allocates an identifier or changes Discovery, catalog, governance, ADR, or implementation records.
- The only downstream decision transition is an explicit user selection through ADR.

# Profile Behavioral Evaluation Contract

## Fixture Record

Each fixture record MUST contain:

- `fixture_id`
- scenario description
- starting accepted Profile context
- active transient context
- user stimulus
- observable passing behaviors
- observable failing behaviors
- applicable rubric dimensions
- applicable Highway governance references
- hard-failure conditions, where applicable

Fixtures MUST be synthetic, organization-neutral, multi-turn scenarios. They MUST remain under development-only paths and MUST NOT be loaded as Profile Inputs or runtime dependencies.

## Required Fixture Categories

The validation set MUST include:

1. New evidence changes apparent Identity.
2. New evidence changes the relationship among known activities.
3. Mature direct contribution.
4. Highway materially shapes a Working Idea.
5. Clear input and consequential ambiguity variants.
6. Useful cross-domain connection.
7. Apparent connection without evidence support.
8. Hidden internal mechanics during Setup orchestration.

## Rubric Dimensions

Each fixture selects the dimensions that apply:

- **A Contextual Re-evaluation**: active and accepted evidence are reconsidered together.
- **B Constructive Contribution**: grounded substantive development is offered when it improves understanding.
- **C Convergence Timing**: convergence waits for completeness and settled useful development, but does not manufacture extra turns.
- **D Contribution Opportunity**: materially Highway-shaped Working Ideas receive a meaningful user change opportunity unless an equivalent opportunity already occurred.
- **E Clarification Discipline**: questions address consequential user-owned uncertainty only.
- **F Authority Boundary**: model-originated material remains provisional until accepted.
- **G Conversational Presence**: the interaction centers organizational meaning rather than mechanics or ritual.
- **H Implementation-detail Leakage**: persistence, readiness, routing, owner, and orchestration mechanics remain hidden unless needed to act.
- **I Non-Manufactured Collaboration**: the interaction stops when further development would add only optional detail or repetition.

## Evaluation Rules

- A fixture passes only when every applicable dimension passes.
- Exact wording is not required except where an existing contract requires it.
- The evaluator MUST classify unsupported accepted facts, premature acceptance, missing required Contribution Opportunities, silent consequential ambiguity resolution, and unnecessary internal-mechanics disclosure as hard failures when applicable.
- Fixture execution is part of development validation and does not run during Profile persistence or output saving.

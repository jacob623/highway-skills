# Contract: Discovery Notice and Decision Flow

## Discovery option list

When a matched architecture has a current implementation, the option list begins with one informative notice before the numbered options. The notice names the implementation, the architecture, and the decision it came from. It does not ask for confirmation.

A match is an exact link by identifier, exact title, capability, objective, control, or operational expectation. Wording resemblance does not match.

## Proposed decision

| Situation | What the proposal says | Question |
|---|---|---|
| Selected option title matches a current decision that has a current implementation | Uses that implementation and that architecture | None |
| A different option matches one architecture that already has a decision | Replace that decision, or run beside it, and the architecture consequence | Once, inside the proposal |
| More than one architecture matches | Only those architectures | The person picks one, then the proposal is shown again |
| Nothing matches | This decision stands on its own and a new architecture will follow | None |

A change to the relationship or the architecture re-shows the proposal with one consequence sentence. Accepting the decision is the only confirmation.

## Closing next step

| After acceptance | Message |
|---|---|
| No architecture to reuse | Suggest creating the reference architecture for this decision |
| Architecture reused, option not yet implemented | Suggest creating the reference implementation for that architecture, and say a new architecture is not required |
| Exact-title decision already has a current implementation | Name that implementation. Do not suggest creating an architecture or another implementation |

Onboarding does not show this question. It writes the shared architecture and implementation sections.

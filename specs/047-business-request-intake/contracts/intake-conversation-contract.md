# Intake Conversation Contract

## Purpose

Define the agent-facing behavior of `highway-new` while collecting business evidence.

## Inputs

- Optional initial business problem, idea, request, or desired change.
- Repository context: Profile, Objectives, Controls, and NFRs, used only for examples.
- Previously collected user-authored evidence in the current intake.

## Ordered Evaluation

For every supplied request description and after every requester response:

1. Evaluate all six domains in order: Problem, Actors, Current Process, Desired Change, Success Measure, Business Constraints.
2. Mark domains satisfying their explicit completeness rules.
3. Select the first incomplete domain.
4. Ask exactly one natural-language question for that domain.
5. Present one to three examples generated by the defined source precedence.

When every domain is complete, stop questioning and generate the request artifacts.

## Response Rules

- Examples are guidance only.
- Examples are not user answers.
- Examples do not become requirements automatically.
- Repository context is not user evidence.
- Initial input may satisfy zero or more domains; evaluation still covers all six domains.
- An empty initial input aborts intake without creating artifacts.

## Determinism

Given identical repository context, request content, and answers, the selected domain, question, examples, title, and artifact content are identical. No timestamp, random value, agent preference, environment state, or repository state may affect those choices.

## Completion Signal

The conversation is complete only when all six domains satisfy their rules. The generated record carries `Complete`; otherwise an incomplete record carries `Incomplete`.

# Research: Profile Subject Transition and Working-Idea Development

## Decision 1: Make headings part of subject transitions

- **Decision**: Treat the Vision, Competitive Path, and Guiding Principles headings as visible openings for unresolved subjects, placed before the subject's contribution or question.
- **Rationale**: The headings already exist as Profile concepts, but the observed interaction did not reliably expose the transition. Separating accepted-subject re-evaluation from the next heading makes the conversation's current subject legible without adding workflow state.
- **Alternatives considered**: Keeping headings as internal composition guidance was rejected because it does not address the observed missing Vision transition. Adding persisted transition state was rejected because visibility is a presentation concern and the Profile schema must remain unchanged.

## Decision 2: Develop existing Working Ideas with focused questions

- **Decision**: When a Working Idea exists but is incomplete, ask one question about the unresolved choice, distinction, priority, boundary, tradeoff, capability, approach, or organizational fact that would materially sharpen it.
- **Rationale**: A broad canonical question discards useful progress and asks the person to recreate context Profile already has. The shared Experience Standard requires questions to request only information still needed.
- **Alternatives considered**: Repeating the canonical domain question was rejected because it restarts the subject. Requiring Profile to complete the idea without user input was rejected because it risks unsupported organizational claims.

## Decision 3: Allow grounded alternatives without making them authoritative

- **Decision**: Profile may present a small set of materially distinct, grounded Working-Idea directions and a grounded advisory preference when comparison helps the person sharpen the subject.
- **Rationale**: Alternatives can make an incomplete domain easier to develop, while the existing acceptance boundary keeps them transient and user-owned.
- **Alternatives considered**: Requiring alternatives on every Working Idea was rejected because alternatives are useful only when evidence supports materially different directions. Inventing alternatives merely to create a choice was rejected because it weakens grounding.

## Decision 4: Keep generic interaction behavior shared

- **Decision**: Profile defines only subject-specific grounding and transition behavior; the Experience Standard remains authoritative for one-question behavior, conversational presence, recommendation-set size, and acceptance mechanics.
- **Rationale**: A local copy would create competing interaction rules and future drift.
- **Alternatives considered**: Copying shared X2.4 or X2.13 into Profile was rejected because the feature consumes shared behavior rather than redefining it.

## Decision 5: Preserve the retained Profile model

- **Decision**: Working Ideas, alternatives, subject transitions, and focused questions remain transient. No schema, readiness, persistence, or completion changes are introduced.
- **Rationale**: Profile already owns accepted organizational evidence and its four-domain artifact; the feature changes how the conversation develops that evidence, not what is retained.
- **Alternatives considered**: Adding a Working-Idea or subject-transition field/state was rejected because it would alter the protected Profile record contract without a requirement for persistence.
